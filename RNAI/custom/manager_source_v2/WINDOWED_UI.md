# 視窗化介面驗收

預設 1000×700，最小 800×600，正常啟動為置中視窗，不自動最大化。已記錄視窗大小及位置；讀取時檢查螢幕工作區，無效或螢幕已移除的座標回到主螢幕。1000×700 的朋友與黑名單採左右雙欄；800×600 改為上下排列。設定卡片在 1200×800 雙欄，1000×700 與 800×600 單欄；卡片較窄時控制項移到說明下方。

| 尺寸／渲染縮放 | 截圖 | 檢查結果 |
|---|---|---|
| 800×600，100% | [戰鬥頁](window_800x600.png)、[名單頁](lists_800x600.png) | 側欄、生命體選擇、內容與頁尾均可見；設定與名單單欄。 |
| 1000×700，100% | [戰鬥頁](window_1000x700.png)、[名單頁](lists_1000x700.png) | 設定單欄；兩份名單左右雙欄。 |
| 1200×800，100% | [戰鬥頁](window_1200x800.png) | 設定雙欄。 |
| 800×600，125% 渲染 | [戰鬥頁](window_800x600_125.png) | 字體及控制項未裁切。 |
| 800×600，150% 渲染 | [戰鬥頁](window_800x600_150.png) | 字體及控制項未裁切。 |

上述 125%／150% 圖片是 WPF 指定 DPI 的離屏渲染；並未實際改變 Windows 顯示器縮放。應用程式宣告 Per Monitor V2 DPI awareness，實體跨螢幕移動仍需人工驗證。

自動化 UI 檢查覆蓋三種尺寸、八個頁面、九種生命體切換、搜尋、未儲存標記、重設，以及外層橫向溢出與控制項邊界檢查。每種生命體的可編輯欄位會被分配到「常用、戰鬥、安全、進階」其中一頁，測試檢查沒有遺漏或重複。資料測試在獨立複本涵蓋九種生命體、名單、技能延遲及配置。原版六頁「常用、戰鬥、安全、進階、名單、Profiles」均保留；對照見 [FEATURE_PARITY.md](FEATURE_PARITY.md)。加入五種 S 型後的選擇器截圖：[800×600](s_types_800x600.png)、[1000×700](s_types_1000x700.png)、[1200×800](s_types_1200x800.png)。遊戲內 AI 生效與完整人工點擊流程尚未驗證。
